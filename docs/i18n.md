# Languages (English, German)

The app speaks English and German. A person gets the language of their browser, or chooses one in
Settings → Language (kept in this browser, `localStorage`; it does not follow the person to another
device). Not translated: this documentation, the demo's sample events, server logs, the texts of
API answers to calendar apps, what people write themselves (names of calendars, views and
categories, event text), and Kanidm's own sign-in page.

## How it works

`app/utils/i18n.ts` holds the language and the functions. **The English text is the key.**

```ts
import { N_, t, tc, tv } from '~/utils/i18n'

t('Enter a title.') // text
t('Copied {name} to your views', { name }) // text with values: never a template literal
tc('{count} booking | {count} bookings', count) // plural: forms split by " | " (two: one | other,
// three: none | one | other); {count} is filled in
const LEVELS = [{ value: 'read', label: N_('Can see') }] // a text in a table or a constant
tv(level.label) // translates it when it is shown
```

- English needs no dictionary and an untranslated text shows in English, so nothing shows as a key.
- `t`, `tc` and `N_` take a **string literal** as their first argument, so the tests can read it.
  Compose sentences with `{values}`, not with `+` or template literals, and put a whole sentence in
  one text (word order differs between languages).
- A sentence with markup inside (a bold value, a link): `tparts('Zone: {zone}. More text')` gives the
  text split at its `{values}`; the template draws the pieces and puts its own element where a
  `{ name }` piece stands (see the example in `app/utils/i18n.ts`). The translation decides the
  word order. Do not translate the pieces of a sentence one by one.
- Call `t` while rendering (in a template or a `computed`) and the screen follows a change of
  language without a reload. A text kept in a variable at load time stays in the language of that
  moment: keep the English with `N_` and call `tv` where it is shown.
- A message that is made once and stored (a problem listed in the sidebar, a "pending" title made
  by the loader) keeps the language of the moment it was made until the next load; a switch in
  Settings does not rewrite it. Show a text with `t` at the moment of drawing where that is cheap.
- Code that the server imports (today `app/utils/ical/read*.ts`, `zone.ts`, `x-properties.ts`,
  imported by `server/utils/resources/reconcile.ts`) must not import `~/utils/i18n`: the server
  bundle has no language and no `~` alias. Its messages stay English; `nuxt build` fails if one
  slips in.
- A text that serves as a key of saved data (`SidebarSection`'s `title`) stays English in the data
  and is translated only where it is drawn.
- Dates: `app/utils/date-names.ts` has the names; formatters take `intlLocale()`.
- Attributes: `:label="t('Edit')"`, `:aria-label="t('Close')"`. Screen reader texts (`aria-label`,
  `sr-only`, `title`, `placeholder`, alerts) are translated like any other.
- The page title: `useHead({ title: () => t('Settings') })`.

German lives in `app/i18n/de/<area>.ts`, one file per area (`'English text': 'German text'`),
listed in `app/i18n/de/index.ts`. A text may be in one area only. A new language is a folder next
to `de` and an entry in `LOCALES` and `DICTIONARIES` (`app/utils/i18n.ts`).

## Checks

`tests/i18n-completeness.test.ts` reads the source and fails when

- the first argument of `t`, `tc` or `N_` is not a plain string literal,
- a text has no German entry, or a German entry has other `{values}` or a different number of
  plural forms than its English text,
- a German entry is not used any more, or the same text is in two areas.

While working on one area: `I18N_ONLY=app/components/settings npx vitest run
tests/i18n-completeness.test.ts` limits the first two checks to those paths.

The English screens must stay as they are: the unit and browser tests read English text.

## German style

- **"du"**, never "Sie". Short and factual: an imperative for a button ("Speichern"), a plain
  sentence for a message ("Der Termin konnte nicht gespeichert werden."). Say "du" only where the
  sentence needs a person ("Du hast keine anstehenden Buchungen.").
- Prefer neutral words (a verb, "Person", "alle") over role nouns. "Administrator" and "Admin" are
  used as in other software.
- Nouns are capitalised, buttons and labels have no final full stop, sentences have one, as in the
  English text. Quotation marks: „so“. Keep the `{values}` as they are, in the right place.
- Short: 360 px wide screens show German about a third longer than English. Prefer the short word.
- Product and standard names stay: CalDAV, iCal, ICS, OIDC, Kanidm, Radicale, URL, WebDAV.
